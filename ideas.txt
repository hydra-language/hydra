CONST PROPAGATION

example:
    fn main() -> void {
        const x = 10;
        let y = 22;

        y = x;
    }

what happens to x? 
    - the value is moved into y and then the variable x is dropped
what happens to y? 
    - the value now changes to whatever x was AND the constness of x propagates to it

this means that y is now a const variable and any attempt to reassign it after 'y = x' while not compile

Conceptual Rules
1. every variable has a mutability state, mutable (let) or const
2. Assigning moves ownership
3. When ownership moves, mutability transfers
    a. let -> let = still mutable
    b. let -> const = now immutable
    c. const -> let = impossible
4. Attempting mutate through const = comptime error
5. Attempting mutate after move to const = comptime error

this seems to, in theory, do everything the Rust borrow checker does,
without lifetimes or reference graph analysis

traits for types

extension blocks for traits for user defined types
    - these trait definitions would live
    in a module like std::traits;
        ex:
            trait Copy {
                fn copy(&self) -> void {}
            }

            trait Drop {
                fn drop(&self) -> void {}
            }

    - the programmer would then include
    then like this:
            include std::traits;

    ex:
        include std::traits;

        struct String {
            /*...*/
        }

        extension Copy, Drop on String {
            fn copy(&self) -> void {
                /*...*/
            }

            fn drop(&self) -> void {
                /*...*/
            }
        }
